# 0003. LLM과 임베딩은 어댑터 뒤에 두고, 기본은 로컬에서 돌린다

- 상태: 제안
- 날짜: 2026-11-18

## 맥락

개발과 측정은 작성자의 노트북(Apple M4 Pro, 메모리 48GB) 한 대에서 한다. 공개 서버는 아직 없다. 나중에 공개 데모를 띄우면 작은 서버에서 로컬 LLM을 돌리기 어렵다. 그때는 API로 바꿔야 한다.

로컬 실행기는 Ollama, LM Studio, MLX(`mlx-lm`), llama.cpp 등이 있고, 대부분 OpenAI 호환 HTTP API를 낸다.

## 결정

1. 앱은 LLM과 임베딩을 어댑터 인터페이스로만 부른다. 어댑터 구현은 OpenAI 호환 HTTP, 외부 API, 가짜(mock) 셋을 둔다.
2. 기본은 로컬이다. 임베딩은 bge-m3, LLM은 7~14B 모델을 쓴다. 실행기와 모델은 같은 평가셋과 같은 부하로 기준선을 잰 뒤 고르고, 그 결과를 이 ADR에 덧붙인다.
3. 부하 측정(k6)에서 워커는 가짜 LLM을 쓴다. 접수 API와 큐의 성능을 LLM 속도와 섞지 않기 위해서다.
4. 공개 데모에 쓸 API 모델과 호스팅은 데모를 띄울 때 새 ADR로 정한다.

## 버린 대안

- 처음부터 외부 API만 쓰기: 평가와 부하 측정을 돌릴 때마다 비용이 든다.
- 실행기 하나에 맞춘 SDK 직접 호출: 실행기나 API로 바꿀 때 코드를 고쳐야 한다.

## 결과

- 실행기 비교(같은 모델, 같은 부하에서 지연과 처리량)를 측정 항목으로 둘 수 있다.
- 가짜 LLM은 실제 LLM의 실패(시간 초과, 빈 응답)를 흉내 내는 모드를 가진다. 테스트가 실제 실패 조건을 가리지 않게 하기 위해서다.
